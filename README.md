# 港口潮位采集演示

用两个本地来源模拟港口潮位采集，演示「接收 → 拼接 → 推送」的完整链路。仅用 Node.js 内置模块，无第三方依赖。所有记录都是可重复生成的虚构数据（固定基准日期 2026-11-21 + 固定随机种子）。

## 运行

```sh
node server.js          # 读取 PORT 环境变量，默认 3000，绑定 127.0.0.1
PORT=4000 node server.js
node --test             # 运行全部用例（正常 + 异常）
```

打开 `http://127.0.0.1:3000`，页面上三个按钮跑真实功能：

- **接收实时潮位**：快速采样源，00–11 时每 10 分钟一条（03–04 时模拟缺测），暂定值。
- **补一段归档测量**：晚到的归档文件，02–05 时的确认值。
- **查看小时交接记录**：接收与推送的完整时序日志。

业务结果区带 `data-evidence-result` 属性，便于核对操作前后内容。

## 设计

- **接收端**：`realtime` 与 `archive` 两个来源各自独立保存，每条记录带测量时间戳与接收时间戳（`lib/tide-store.js` 的 `readings` / `receipts`）。
- **拼接端**：逐小时合并，首末小时之间的空洞显式标为缺口；归档到达时标明「补齐缺口」与「替换范围」；两种可用方式——
  - `prefer-fast`（先保快速读数）：确认值到达前先用快速读数（暂定），确认值一到即替换；
  - `confirmed-only`（只给确认值）：没有归档确认的小时一律不发布。
- **推送端**：每次接收后只把合并结果发生变化的小时重发（记入 `pushes` 与交接记录），重复接收相同数据不产生重发。

页面逐小时展示「谁补了哪段」（来源列）以及「什么还不确定」（缺口 / 暂定 / 未确认区间）。

## API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 演示页面 |
| GET | `/api/state?mode=prefer-fast\|confirmed-only` | 完整状态（来源、逐小时、不确定区间、交接记录） |
| POST | `/api/ingest/realtime` | 接收演示用实时批次 |
| POST | `/api/ingest/archive` | 接收演示用归档批次 |
| POST | `/api/ingest` | 通用接收：`{"source":"realtime"\|"archive","records":[{"time","height"}]}` |
| POST | `/api/reset` | 重置为空的演示环境 |

异常均返回 4xx JSON：未知来源 / 空记录 / 时间无法解析 / 高度非数值 / 未知拼接方式 → 400；未知路径 → 404；方法不允许 → 405。

## 文件

- `server.js` — HTTP 服务（`node:http`）
- `lib/tide-store.js` — 接收 / 拼接 / 推送核心逻辑
- `lib/demo-data.js` — 可重复生成的虚构潮位记录
- `lib/page.js` — 演示页面
- `test/tide.test.js` — `node --test` 用例
